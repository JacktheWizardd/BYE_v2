# BYE light-load benchmark

Run from the BYE root with Node 24 (or an absolute Node executable). Only target the existing free development project. No dependencies are installed by these scripts.

1. `node backEnd/scripts/benchmark/session.mjs` creates a new anonymous reader using an owner-created single-use invite. Owner credentials stay in the ignored backend session file; the new reader session is ignored and mode 0600.
2. During an explicitly authorized measurement window, set `supabase/functions/bye-api/benchmark-config.ts` to the disposable reader IDs and deploy `bye-api`. The committed/default value is **null**. Never add an owner ID. Benchmark parameters are denied when disabled. `/me` must expose timing or the runner refuses to continue.
3. Build with `VITE_BENCHMARK=true` and Vite preview on **localhost:5173**. This build uses `bye-benchmark-auth`, separate from normal browser Auth storage. `session.mjs browser-invite` prepares a second disposable reader for the actual browser invite flow. Add that reader to the temporary server allowlist after redemption. Never paste an owner token into a browser.
4. `node backEnd/scripts/benchmark/run.mjs before` and `... after` save sanitized JSON. Optional `BYE_FAMILY=sections` selects one stage. Each route/concurrency gets three excluded warmups and thirty measured samples. One global start scheduler inside the process spaces starts by 105 ms; concurrency is at most ten. Do not run another live workload concurrently. Count browser/source/diagnostic calls in the same pass's 2,500-request ledger.
5. Record browser milestones from the hidden development-only `#bye-benchmark` output. It exposes timing, action kinds, status and route families, never request headers, URLs, names or review bodies. Use the actual UI; the browser command recipe and run state are described in the report.
6. `source.mjs` is the bounded source experiment recorded for this run. Its chosen instructor is now cached: **do not present subsequent executions as cold measurements**. To repeat, first identify a naturally missing candidate/profile in the database; never delete cache entries to manufacture a miss. At most one profile operation (three candidate pages × three attempts plus three profile attempts) and one review operation (three attempts) give the conservative fifteen-attempt ceiling. Stop after source failure; honor the backend's returned cooldown.
7. `preflight.mjs` records three synthetic OPTIONS probes. These are separate from browser preflight counts.
8. Revoke both disposable readers with `session.mjs revoke` and `session.mjs revoke-browser`; verify access denial. Restore the server allowlist to null and deploy, rebuild without VITE_BENCHMARK, and restore Vite dev on 5173.

The cache-only implementation reads backend-only validated entries, applies the six-hour fresh/24-hour hard expiry limits, and still enforces instructor identity and membership. It does not fill caches, wait for fills, contact RMP, or update LRU timestamps. Consequently its distributed read timing is not a load test of the normal cache-fill coordinator. Stale candidate results cannot auto-link an identity. Misses return 409 `rmp_cache_miss`.

Stage safety stops: two consecutive unexpected 401/403 responses, three consecutive timeouts, or >5% 5xx after twenty samples. Retry-After postpones future starts instead of retrying the sample. Normal authentication checks, freshness, source concurrency and source cooldowns remain unchanged. This is a small sample benchmark, not a capacity guarantee.
