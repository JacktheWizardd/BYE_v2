# Published semesters and freshness
The published terms route adds scope=published to the existing pagination envelope, with an imported boolean. Imported-only listing stays compatible.

POST /v1/schools/{school}/terms/{term}/load validates a saved published term and shares one catalog job; GET the same path ending in /status for reader-safe progress. A 202 response means queued. Owner imports remain owner-only. Browser database roles cannot read the directory or execute its RPC.

The worker refreshes the directory daily through its existing source lease. Failed reads preserve the previous directory. Previously imported terms remain available if removed upstream. Imports wait for the global five-minute start deadline; multiple semesters share capacity. Successful refreshes schedule against that reserved deadline. Five minutes is a freshness threshold, not a per-term guarantee.

The frontend checks progress every 15 seconds while visible and cancels obsolete reads. Course search waits for publication. Up-to-date, older counts, queued/running work and failed browser reads are distinct. Refresh all rereads stored data and never advances source timestamps.

Verification includes regression suites and deployed rollback transactions: repeated loads share one job, unpublished IDs are rejected, and browser table/RPC privileges are denied. The RLS-without-policies advisory is intentional for this backend-only table. Existing platform warnings remain outside this feature.

## Automatic preload
Daily validated directory publication now queues every missing published term, newest first. Existing queued jobs keep their FIFO position. Repeated preload/selection reuses outstanding jobs. Queue ties use a persisted identity sequence. Status includes server observation time, eligible jobs ahead, global fetch deadline, attempts and retry-not-before. The deadline is not a per-semester ETA. Imported terms expose ready; unimported terms expose preparing/queued/running/failed. Initial imports are checked every five seconds while visible; all selector labels reload as the shared batch progresses. Queued work uses a clock/count rather than a fake percentage bar. Source starts remain at least five minutes apart. Final batch outcomes are saved to exports/preload-semesters-verification.json.
